## Key Architecture Concepts

### Bundle-Based Domain-Driven Design

SolidInvoice follows **Domain-Driven Design (DDD)** principles using Symfony's bundle system. Each bundle represents a distinct business domain with its own:

- **Entities**: Domain models and database entities
- **Repositories**: Data access layer
- **Actions**: Single-purpose controllers (ADR pattern)
- **Form Handlers**: Form processing logic
- **Event Listeners**: Domain event handling
- **Resources**: Templates, translations, configurations
- **Tests**: Unit and functional tests

### Bundle Structure Pattern

Each business bundle follows this consistent structure:
```
src/ExampleBundle/
├── Action/             # Controllers (Action-Domain-Responder pattern)
│   ├── Ajax/          # AJAX-specific actions
│   └── Transition/    # Workflow transition actions
├── DataGrid/          # Data grid configurations
├── DependencyInjection/ # Bundle configuration and services
├── Entity/            # Doctrine entities and value objects
├── Event/             # Domain events and event classes
├── Form/              # Form types and handlers
│   ├── Handler/       # Form processing logic
│   └── Type/          # Symfony form types
├── Listener/          # Event listeners and subscribers
│   ├── Doctrine/      # Database event listeners
│   └── Mailer/        # Email-related listeners
├── Menu/              # Menu builders and configurations
├── Repository/        # Doctrine repositories
├── Resources/         # Bundle resources
│   ├── config/        # Service and routing configurations
│   ├── translations/  # Translation files
│   └── views/         # Twig templates
├── Test/              # Test utilities and factories
├── Tests/             # Unit and functional tests
├── Twig/              # Twig extensions and components
│   └── Components/    # Live Components and Twig Components
└── SolidInvoiceExampleBundle.php # Bundle class
```

## Core Business Domains

### ClientBundle - Customer Management
- **Purpose**: Manage clients, contacts, addresses, and credit balances
- **Key Entities**: Client, Contact, Address, AdditionalContactDetail, Credit
- **Features**: Multi-contact support, geographic data, credit tracking

### InvoiceBundle - Billing Management
- **Purpose**: Create, manage, and track invoices and recurring billing
- **Key Entities**: Invoice, RecurringInvoice, Line, RecurringOptions
- **Features**: PDF generation, email delivery, recurring schedules, workflow states

### QuoteBundle - Estimate Management
- **Purpose**: Generate quotes/estimates and convert to invoices
- **Key Entities**: Quote, Line
- **Features**: Quote-to-invoice conversion, PDF generation, approval workflow

### PaymentBundle - Payment Processing
- **Purpose**: Handle payments through multiple gateways
- **Key Entities**: Payment, PaymentMethod, SecurityToken
- **Features**: Payum integration, bank transfers, online payments

### UserBundle - Authentication & Authorization
- **Purpose**: User management, authentication, and API access
- **Key Entities**: User, ApiToken, UserInvitation
- **Features**: OAuth integration, API tokens, user invitations

## Development Workflow

### Common Development Tasks

1. **Adding a New Feature to Existing Bundle**:
   - Create Action in `src/BundleName/Action/`
   - Add Entity if needed in `src/BundleName/Entity/`
   - Create Form Handler in `src/BundleName/Form/Handler/`
   - Add templates in `src/BundleName/Resources/views/`
   - Write tests in `src/BundleName/Tests/`

2. **Creating a New Bundle**:
   - Follow the bundle structure pattern
   - Register in `config/bundles.php`
   - Add routing configuration
   - Implement bundle class extending Symfony\Component\HttpKernel\Bundle\Bundle

3. **Frontend Development**:
   - Add Stimulus controllers in `assets/controllers/`
   - Create Twig Components in bundle's `Twig/Components/`
   - Add styles in `assets/scss/`
   - Run `bun run dev` for development builds

### Key Configuration Files

- **composer.json**: PHP dependencies, autoloading, project metadata
- **package.json**: Node.js dependencies, build scripts
- **webpack.config.js**: Asset compilation configuration
- **config/services.php**: Dependency injection configuration
- **config/packages/**: Framework and bundle configurations

### Testing Strategy

- **Unit Tests**: Located in each bundle's `Tests/` directory
- **Functional Tests**: API and integration tests
- **Test Factories**: Using Foundry for entity creation
- **Test Traits**: Shared testing utilities in `CoreBundle/Test/Traits/`

## API Development

### API Platform Integration
- **REST API**: Automatic API generation for entities
- **OpenAPI Documentation**: Auto-generated API documentation
- **Authentication**: API token-based authentication
- **Serialization**: Custom normalizers for complex data types

### API Structure
- API endpoints are automatically generated from entities
- Custom API logic in `ApiBundle/`
- Authentication handled by `ApiBundle/Security/`
- Custom normalizers in `ApiBundle/Serializer/Normalizer/`

## Database Architecture

### Migration Management
- **Doctrine Migrations**: Version-controlled database changes
- **Migration Files**: Located in `migrations/` directory
- **Entity Mapping**: Annotations/attributes in entity classes
- **Multi-tenant Support**: Company-based data isolation

### Key Database Concepts
- **Company Isolation**: All business data is company-scoped
- **Soft Deletes**: Archivable entities for data retention
- **Audit Trails**: Timestampable entities for change tracking
- **Custom Types**: Money, JSON array, and other custom Doctrine types
